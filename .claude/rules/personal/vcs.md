# Version control

- Always use `jj` for VCS operations. Fall back to `git` only when there is no
  `jj` repo (i.e. no colocated `.jj` directory).
- Do each isolated change in its own `jj` revision. If there is no `jj` repo,
  make a `git` commit for each isolated change.
- Never modify VCS history (rebase, amend, reset, force-push, squash, etc.)
  without asking first.
- Never create a `jj` bookmark without asking first.
- Never create a pull request without asking first.

## Commit messages

- Write a first line of 70 characters maximum. Start with a capitalized
  imperative verb: `Add`, `Fix`, `Refactor`, `Remove`. Do not add trailing
  punctuation.
- Make the first line specific. A reader of `jj log` must understand the change
  without the diff.
- If the first line tells the whole story, stop there.
- If it does not, add a blank line. Then write one or more paragraphs for the
  context: why you made the change, or how it works. Wrap each line at 80
  characters.
- Give the context that the diff does not show. Do not restate the diff, for
  example "change X from A to B in file F".
- Name a non-obvious side effect, tradeoff, or constraint.
- Do not add an attribution footer or a "generated by" line.
